# راهنمای ساخت پلاگین نگار

این سند برای توسعه‌دهنده‌ای است که می‌خواهد بدون دست زدن به هسته، به نگار امکان تازه اضافه کند. مدل پلاگین عمداً شبیه وردپرس است: یک پوشه، یک شناسنامه، و فعال‌سازی از پنل. زبان قالب سایت Next.js و زبان سرور Go است؛ پلاگین معمولی هیچ‌کدام را دوباره کامپایل نمی‌کند.

اگر فقط می‌خواهید کد آنالیتیکس یا CSS تزریق کنید، پلاگین آمادهٔ **کد سفارشی** (`plugins/wpcode`) را باز کنید و این راهنما را از بخش «پلاگین کد سفارشی» بخوانید.

## ۱. ایدهٔ کلی

```
plugins/
  my-plugin/
    plugin.json      الزامی — شناسنامه
    blocks.json      اختیاری — قطعه‌های صفحه‌ساز
    admin.json       اختیاری — فرم تنظیمات در پنل
    assets/          اختیاری — css، js، تصویر
    README.md        اختیاری — توضیح برای انسان
```

سرور هنگام بالا آمدن `plugins/*/plugin.json` را می‌خواند. شناسهٔ داخل فایل باید با نام پوشه یکی باشد. رکورد فعال/غیرفعال در پایگاه PocketBase، مجموعهٔ `plugins`، نگه داشته می‌شود. خاموش کردن پلاگین فایل را پاک نمی‌کند؛ فقط اثر عمومی‌اش (قطعه، استایل، تزریق) قطع می‌شود.

دو راه نصب:

1. پوشه را در `plugins/` بگذارید و سرویس `negar-api` را ری‌استارت کنید.
2. از پنل، مسیر «پلاگین‌ها»، یک فایل zip بارگذاری کنید. زیپ همان لحظه استخراج و ثبت می‌شود و نیازی به ری‌استارت نیست.

## ۲. plugin.json

```json
{
  "id": "my-plugin",
  "name": "نام نمایشی",
  "version": "1.0.0",
  "description": "یک جمله که در فهرست پلاگین‌ها دیده می‌شود.",
  "author": "نام شما",
  "minCms": "1.0.0",
  "admin": {
    "menu": "عنوان در منوی پنل",
    "route": "/master/plugins/view/my-plugin"
  },
  "assets": ["assets/style.css", "assets/front.js"]
}
```

| فیلد | الزام | توضیح |
| --- | --- | --- |
| `id` | بله | فقط حرف کوچک انگلیسی، عدد و خط تیره. با حرف یا عدد شروع شود. ۲ تا ۴۹ نویسه. باید با نام پوشه برابر باشد. |
| `name` | بله | نام انسانی، ترجیحاً فارسی. |
| `version` | خیر | رشتهٔ آزاد. پیش‌فرض `0.0.0`. |
| `description` | خیر | در کارت پلاگین نشان داده می‌شود. |
| `author` | خیر | |
| `minCms` | خیر | برای یادآوری سازگاری. هسته فعلاً آن را سخت‌گیرانه مقایسه نمی‌کند. |
| `admin.menu` | خیر | اگر باشد، پیوندی در نوار پنل ساخته می‌شود. |
| `admin.route` | خیر | مسیر پنل. برای فرم عمومی از `/master/plugins/view/{id}` استفاده کنید. فقط وقتی مسیر اختصاصی در هسته دارید (مثل کد سفارشی) مسیر دیگری بگذارید. |
| `assets` | خیر | مسیرهای نسبی داخل پوشهٔ پلاگین. وقتی پلاگین روشن است، CSS و JS در صفحهٔ عمومی لینک می‌شوند. |

شناسهٔ `wpcode` رزرو است و از پنل حذف نمی‌شود. می‌توان آن را غیرفعال کرد.

## ۳. قطعهٔ صفحه‌ساز — blocks.json

آرایه‌ای از قطعه‌ها. هر قطعه در کتابخانهٔ صفحه‌ساز، گروه دلخواه شما، ظاهر می‌شود و مدیر آن را داخل ستون می‌گذارد.

```json
[
  {
    "type": "my-plugin-note",
    "label": "یادداشت",
    "group": "افزونه",
    "icon": "badge",
    "defaults": { "title": "توجه", "body": "متن" },
    "fields": [
      { "key": "title", "label": "عنوان", "type": "text" },
      { "key": "body", "label": "متن", "type": "textarea" },
      {
        "key": "tone",
        "label": "حالت",
        "type": "select",
        "options": [
          { "value": "pine", "label": "آرام" },
          { "value": "copper", "label": "تأکید" }
        ]
      }
    ],
    "template": "<aside class=\"note note-{{tone}}\"><strong>{{title}}</strong><p>{{body}}</p></aside>"
  }
]
```

### قانون نام `type`

با شناسهٔ پلاگین شروع کنید تا با هسته تصادم نکند: `my-plugin-note` نه `text`. هسته این نام‌ها را از قبل دارد و اگر تکرار کنید، قطعهٔ هسته برنده است:

`heading` `text` `image` `button` `hero` `features` `cards` `stats` `faq` `quote` `cta` `pricing` `testimonials` `gallery` `video` `form` `posts` `html` `alert` `tabs` `logos` `spacer` `divider`

### فیلدهای پشتیبانی‌شده در بازرس

| type | نتیجه |
| --- | --- |
| `text` | ورودی یک‌خطی |
| `textarea` | متن چندخطی |
| `number` | عدد |
| `color` | انتخاب رنگ |
| `url` | پیوند |
| `bool` | کلید روشن/خاموش |
| `select` | فهرست `options` با `value` و `label` |
| `image` | انتخاب از مرکز رسانه؛ مقدار، نشانی فایل است |
| `list` | فهرست تکرارشونده. `itemFields` آرایه‌ای از همان فیلدهاست (بدون list تو در تو). مقدار ذخیره‌شده آرایهٔ شیء است. |

### قالب

موتور قالب عمداً کوچک است و کد اجرا نمی‌کند.

- `{{name}}` مقدار را HTML-escape می‌کند. پیش‌فرض امن همین است.
- `{{{name}}}` مقدار خام. فقط وقتی لازم است که خودتان HTML مطمئن ذخیره کرده باشید.
- `{{#items}} ... {{/items}}` اگر `items` آرایه باشد، بدنه برای هر عضو تکرار می‌شود. عضو اگر شیء باشد، کلیدهایش در دسترس‌اند: `{{title}}`. اگر رشته باشد، کل بدنه با همان رشتهٔ escape‌شده جایگزین نمی‌شود؛ داخل بلوک از فیلدهای شیء استفاده کنید.

نمونهٔ فهرست:

```json
"defaults": {
  "items": [{ "title": "یک", "text": "توضیح" }]
},
"fields": [
  {
    "key": "items",
    "label": "موارد",
    "type": "list",
    "itemFields": [
      { "key": "title", "label": "عنوان", "type": "text" },
      { "key": "text", "label": "متن", "type": "textarea" }
    ]
  }
],
"template": "<ul>{{#items}}<li><b>{{title}}</b> — {{text}}</li>{{/items}}</ul>"
```

استایل قطعه را در `assets/*.css` بگذارید و در `plugin.json` معرفی کنید. کلاس‌ها را با پیشوند شناسهٔ پلاگین شروع کنید تا با هسته تداخل نکنند: `.my-plugin-note` نه `.note`.

## ۴. فرم تنظیمات — admin.json

اگر پلاگین شما به صفحهٔ اختصاصی در هسته نیاز ندارد، تنظیمات را اعلامی توصیف کنید:

```json
{
  "title": "تنظیمات افزونهٔ من",
  "intro": "این متن بالای فرم دیده می‌شود.",
  "fields": [
    { "key": "token", "label": "کلید", "type": "text" },
    { "key": "message", "label": "پیام", "type": "textarea" },
    {
      "key": "mode",
      "label": "حالت",
      "type": "select",
      "options": [
        { "value": "off", "label": "خاموش" },
        { "value": "on", "label": "روشن" }
      ]
    }
  ]
}
```

پنل این فرم را در `/master/plugins/view/my-plugin` می‌سازد و مقدار را در مجموعهٔ `plugin_settings` با فیلد `plugin_id` ذخیره می‌کند. شکل رکورد:

```json
{ "plugin_id": "my-plugin", "data": { "token": "...", "message": "...", "mode": "on" } }
```

خواندن از بیرون پنل، با همان قاعدهٔ دسترسی کارکنان است. یک پلاگین اعلامی به این رکورد از مرورگر مدیر دسترسی دارد؛ اگر منطق سروری لازم دارید بخش ۸ را ببینید.

`admin.route` را اگر خالی بگذارید و `admin.json` وجود داشته باشد، منوی پنل خودش به مسیر `view/{id}` می‌رود. اگر هر دو را پر کردید، `admin.route` همان پیوند منو است.

## ۵. فایل‌های ایستا

هر فایلی زیر پوشهٔ پلاگین از این مسیر سرو می‌شود، فقط وقتی پلاگین روشن است:

```
/pb/api/negar/plugin-assets/{id}/{path}
```

روی سرور واقعی، Caddy پیشوند `/pb` را برمی‌دارد و به برنامهٔ Go می‌رسد. مسیرهای `..` رد می‌شوند. نوع فایل از پسوند حدس زده می‌شود: css، js، svg، png، jpg، webp، json، woff2.

در `assets` فقط فایل‌هایی را فهرست کنید که باید خودکار در سایت عمومی بیایند. بقیه را با نشانی مستقیم صدا بزنید.

## ۶. بسته‌بندی zip

ریشهٔ زیپ یا خود `plugin.json` است، یا یک پوشه که داخلش `plugin.json` باشد:

```
my-plugin.zip
  plugin.json
  blocks.json
  assets/style.css
```

یا:

```
my-plugin.zip
  my-plugin/plugin.json
  my-plugin/blocks.json
```

حداکثر حجم ۲۰ مگابایت است. نصب از نقش مدیر و ویرایشگر ممکن است. حذف فقط برای مدیر است و پوشه را از دیسک پاک می‌کند.

## ۷. پلاگین کد سفارشی (wpcode)

این پلاگین در مخزن هست و صفحهٔ پنلش در هسته ساخته شده، چون ویرایشگر کد، فهرست، اولویت و شورت‌کد از یک فرم اعلامی پیچیده‌تر است. شناسنامه‌اش:

```json
{
  "id": "wpcode",
  "name": "کد سفارشی",
  "admin": { "menu": "کد سفارشی", "route": "/master/plugins/wpcode" }
}
```

قطعه‌ها در مجموعهٔ `snippets` ذخیره می‌شوند:

| فیلد | معنی |
| --- | --- |
| `name` | نام داخلی |
| `code` | خود کد |
| `kind` | `html` یا `css` یا `js` یا `jsonld` |
| `location` | `head` یا `body_open` یا `body_close` یا `footer` |
| `scope` | `all` یا `pages` |
| `slugs` | اگر scope برابر pages است، نامک‌ها با ویرگول |
| `priority` | عدد صحیح؛ بزرگ‌تر زودتر می‌آید |
| `enabled` | بولی |

سرور فقط وقتی پلاگین `wpcode` روشن است این قطعه‌ها را در پاسخ `/api/negar/runtime` می‌گذارد. فرانت‌اند عمومی بر اساس مسیر فعلی (`x-pathname`) تصمیم می‌گیرد کدام را چاپ کند.

شورت‌کد، در HTML مقاله و در قطعهٔ HTML صفحه‌ساز:

```
[snippet id="شناسهٔ رکورد"]
```

جایگزینی سمت سرور هنگام رندر انجام می‌شود. قطعهٔ غیرفعال یا پلاگین خاموش، شورت‌کد را دست‌نخورده می‌گذارد تا معلوم باشد چیزی جا افتاده است.

### الگوی پیشنهادی برای آنالیتیکس

1. پنل → کد سفارشی → قطعهٔ تازه
2. نوع: JavaScript
3. جا: سر صفحه
4. محدوده: همهٔ صفحه‌ها
5. فعال، سپس ذخیره
6. یک صفحهٔ عمومی را با منبع مرورگر باز کنید و وجود `<script>` را در `<head>` ببینید

برای JSON-LD همان مراحل با نوع JSON-LD و جای سر صفحه. هسته آن را داخل `<script type="application/ld+json">` می‌گذارد.

## ۸. وقتی اعلام کافی نیست

پلاگین پوشه‌ای کد Go یا React را کامپایل نمی‌کند. این تصمیم عمدی است: نصب روی سرور مشتری نباید به زنجیرهٔ ساخت شما وابسته باشد، و بارگذاری `.so` بین نسخه‌های Go شکننده است.

اگر رفتار سروری خاص لازم دارید، به ترتیب این‌ها را ترجیح بدهید:

1. **قالب + CSS + فرم تنظیمات.** بیشتر ویجت‌ها همین‌جا تمام می‌شوند.
2. **کد سفارشی.** برای اسکریپت شخص ثالث.
3. **مجموعهٔ PocketBase.** از پنل پایگاه (`/pb/_/` با حساب سوپریوزر نصب) یک مجموعه بسازید و از مرورگر، با SDK رسمی `pocketbase` و توکن کاربر، بخوانید و بنویسید. قاعدهٔ API را محدود کنید.
4. **تغییر هسته.** اگر واقعاً هوک Go لازم است، کد را در `backend/internal` اضافه کنید و یک پلاگین پوشه‌ای هم برای معرفی در پنل کنارش بگذارید. این دیگر پلاگین قطره‌ای نیست و با به‌روزرسانی مخزن باید دوباره ادغام شود.

خواندن تنظیمات پلاگین از یک صفحهٔ سفارشی که خودتان در فرانت اضافه کرده‌اید:

```ts
const pb = new PocketBase(base)
await pb.collection("users").authWithPassword(email, password)
const rec = await pb
  .collection("plugin_settings")
  .getFirstListItem('plugin_id="my-plugin"')
console.log(rec.data)
```

قاعدهٔ این مجموعه فقط کارکنان (مدیر، ویرایشگر، نویسنده) است. بازدیدکنندهٔ عمومی آن را نمی‌بیند. اگر مقداری باید عمومی شود، آن را در قطعهٔ صفحه‌ساز یا در یک رکورد با قاعدهٔ خواندن عمومی نگه دارید، نه در تنظیمات خصوصی.

## ۹. قرارداد اجرایی

پاسخ `GET /api/negar/runtime` شکل تقریبی زیر را دارد. صفحهٔ عمومی همین را می‌خواند:

```json
{
  "settings": { "site_name": "نگار", "menu": [{ "label": "خانه", "href": "/" }] },
  "snippets": [{ "id": "...", "kind": "js", "location": "head", "scope": "all", "code": "..." }],
  "plugins": [
    {
      "id": "example-badge",
      "enabled": true,
      "assets": ["/api/negar/plugin-assets/example-badge/assets/badge.css"],
      "blocks": [],
      "settingsForm": {}
    }
  ]
}
```

`snippets` فقط با روشن بودن `wpcode` پر می‌شود. `plugins` در این مسیر فقط پلاگین‌های روشن را دارد. مسیر کارکنان `GET /api/negar/plugins` خاموش‌ها را هم برمی‌گرداند.

دیگر مسیرها:

| روش و مسیر | نقش | کار |
| --- | --- | --- |
| `POST /api/negar/plugins/{id}/toggle` | مدیر، ویرایشگر | روشن/خاموش |
| `POST /api/negar/plugins/install` | مدیر، ویرایشگر | فیلد فایل `file`، zip |
| `DELETE /api/negar/plugins/{id}` | مدیر | حذف پوشه، به‌جز wpcode |
| `POST /api/negar/me` | هر کارمند | نام و تغییر رمز با `oldPassword` |

روی دامنهٔ عمومی همهٔ این‌ها زیر `/pb` هستند. نمونه: `https://example.com/pb/api/negar/runtime`.

## ۱۰. چک‌لیست انتشار پلاگین

1. `id` یکتا و برابر نام پوشه است.
2. `blocks.json` اگر هست، JSON معتبر است و `type`ها پیشوند دارند.
3. قالب با `{{ }}` نوشته شده، نه با HTML خامِ ورودی کاربر، مگر اینکه دلیل داشته باشید و از `{{{ }}}` آگاه باشید.
4. CSS پیشوند دارد و در `assets` فهرست شده است.
5. zip را یک بار در یک نصب آزمایشی از پنل بالا آورده‌اید.
6. پلاگین را خاموش کرده‌اید و مطمئن شده‌اید استایل و قطعه‌اش از سایت عمومی می‌رود.
7. README داخل پوشه نوشته‌اید: چه می‌کند، چه تنظیماتی دارد، و چه چیزی را عمداً انجام نمی‌دهد.

## ۱۱. اشتباه‌های رایج

- نام پوشه `MyPlugin` است ولی `id` باید کاملاً کوچک باشد. هر دو را `my-plugin` بگذارید.
- `plugin.json` دو سطح تو در تو داخل زیپ است (`dist/my-plugin/plugin.json`). استخراج فقط ریشه یا یک پوشه را می‌پذیرد.
- قطعه‌ای به نام `button` ساخته‌اید و تعجب می‌کنید که رندر هسته می‌آید. نام را عوض کنید.
- در قالب از `{{html}}` برای متن غنی استفاده کرده‌اید و تگ‌ها دیده می‌شوند. یا متن را ساده نگه دارید، یا آگاهانه `{{{html}}}` بگذارید.
- استایل را فقط در پیش‌نمایش پنل انتظار دارید. دارایی‌ها روی صفحهٔ عمومی لینک می‌شوند، نه داخل بوم مدیریت. در بوم، قالب همان HTML را می‌سازد؛ اگر کلاس را نمی‌بینید، یک `<style>` کوچک داخل قالب بگذارید یا بوم را بعد از انتشار چک کنید.
- سرویس را بعد از کپی دستی پوشه ری‌استارت نکرده‌اید. نصب از پنل این مرحله را خودش انجام می‌دهد.
- رمز سوپریوزر PocketBase را با کاربر پنل `/master` اشتباه گرفته‌اید. هر دو هنگام نصب با یک ایمیل و رمز ساخته می‌شوند، ولی پایگاه روی `/pb/_/` است و پنل سایت روی `/master`.

## ۱۲. نمونهٔ کامل

پلاگین `plugins/example-badge` در همین مخزن هر سه لایه را دارد: شناسنامه، یک قطعه، یک CSS و یک `admin.json`. آن را کپی کنید، شناسه را عوض کنید، و به‌عنوان نقطهٔ شروع پلاگین خودتان استفاده کنید. توضیحات کوتاه داخل `plugins/example-badge/README.md` است.

نسخهٔ همین راهنما در سایت نصب‌شده، مسیر `/developers`، هم خوانده می‌شود.
