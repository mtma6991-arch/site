# راهنمای ساخت افزونه برای نگار

نگار دو راه برای گسترش دارد. راه اول فایل و JSON است و بدون بازسازی سایت کار می‌کند. راه دوم کد Go یا React است و بعد از افزودن باید روی سرور `site rebuild` اجرا شود.

افزونهٔ همراه، **کد سفارشی** (`plugins/wpcode`) است و کارش مثل WPCode وردپرس است: تزریق HTML و CSS و JavaScript. نمونهٔ دوم `plugins/example-notice` یک المان صفحه‌ساز بدون کد است.

## ۱. افزونه چیست

هر افزونه یک پوشه داخل `plugins/` است و حتماً `plugin.json` دارد.

```
plugins/my-plugin/
  plugin.json
  elements.json      اختیاری، المان صفحه‌ساز
  README.md          اختیاری
  assets/style.css   اختیاری، فعلاً فقط برای مستندسازی همراه افزونه
```

شناسه (`slug`) فقط حروف کوچک انگلیسی، عدد و خط تیره است و با حرف شروع می‌شود. نام پوشه باید همان شناسه باشد.

## ۲. plugin.json

```json
{
  "name": "نام نمایشی",
  "slug": "my-plugin",
  "version": "1.0.0",
  "description": "یک جمله که در پنل دیده می‌شود",
  "author": "نام شما",
  "minCms": "1.0.0",
  "elements": "elements.json",
  "admin": { "menu": "تنظیم افزونه", "path": "/master/plugins/my-plugin" },
  "capabilities": ["elements"]
}
```

- `elements` اگر باشد، صفحه‌ساز آن فایل را می‌خواند.
- `admin.path` اگر پر باشد و افزونه روشن باشد، در کارت افزونه لینک می‌شود. صفحه را خودتان در فرانت می‌سازید و برای دیده‌شدنش باید فرانت بازسازی شود.
- `capabilities` فقط توضیح است: `elements`، `snippets`، `admin`.

روشن و خاموش بودن در پایگاه PocketBase، مجموعهٔ `plugin_states`، نگه داشته می‌شود. افزونهٔ جدید بعد از نصب زیپ خاموش است تا خودتان روشنش کنید. `wpcode` بار اول روشن است.

## ۳. المان صفحه‌ساز بدون کامپایل

`elements.json` یک آرایه است.

```json
[
  {
    "type": "notice_bar",
    "label": "نوار اعلان",
    "category": "پلاگین",
    "props": [
      { "key": "title", "label": "عنوان", "type": "text", "default": "توجه" },
      { "key": "text", "label": "متن", "type": "textarea", "default": "متن" },
      {
        "key": "tone",
        "label": "لحن",
        "type": "select",
        "default": "info",
        "options": [
          { "value": "info", "label": "اطلاع" },
          { "value": "warn", "label": "هشدار" }
        ]
      }
    ]
  }
]
```

نوع‌های فیلد که بازرس صفحه‌ساز می‌شناسد:

- `text` `textarea` `number` `url` `color`
- `select` با `options`
- `switch` مقدار درست یا نادرست
- `align` راست، وسط، چپ
- `image` انتخاب از مرکز رسانه
- `repeater` با `itemFields` برای فهرست تکرارشونده

`type` المان نباید با المان‌های هسته یکی باشد (مثل `hero` یا `heading`). هسته برنده است.

رندر پیش‌فرض برای المان ناشناخته یک جعبه است: اگر `title` و `text` و `tone` داشته باشید همان‌ها نشان داده می‌شوند. برای ظاهر کاملاً سفارشی، بخش React را ببینید.

افزونه را در پنل روشن کنید و صفحه را در صفحه‌ساز تازه باز کنید. نیازی به ری‌استارت نیست.

## ۴. نصب از پنل

زیپ را طوری بسازید که `plugin.json` یا در ریشه باشد یا تنها پوشهٔ داخل زیپ باشد.

در پنل: افزونه‌ها، «نصب زیپ». مسیرهای `..` رد می‌شوند. سقف حجم ۲۰ مگابایت است.

اگر داخل زیپ فایل `.go` باشد، پاسخ `needsRebuild` می‌دهد. روی سرور:

```bash
sudo site rebuild
```

## ۵. افزونه کد سفارشی

این افزونه منطق جدا در Go ندارد. قابلیت اسنیپت در هسته است و با روشن بودن `wpcode` در سایت عمومی تزریق می‌شود.

- نوع HTML: محل هدر، ابتدای بدنه، فوتر، یا فقط شورت‌کد
- نوع CSS: در همهٔ صفحه‌هایی که اسنیپت به آن‌ها می‌خورد، داخل `<style>`
- نوع JavaScript: هدر یا فوتر
- نوع شورت‌کد: با `[[snippet:شناسه]]` در بلوک HTML، متن غنی، و بلوک «شورت‌کد»

فیلد صفحات: خالی یعنی همه‌جا. چند نامک را با ویرگول جدا کنید. اولویت عدد کوچک‌تر زودتر اجرا می‌شود.

این کد مثل WPCode از طرف مدیر سایت است و پاکسازی نمی‌شود. فقط به کسی که اعتماد دارید دسترسی مدیر بدهید. JavaScript سمت بازدیدکننده اجرا می‌شود، نه روی سرور. PHP وجود ندارد.

## ۶. افزونه React

اگر جعبهٔ پیش‌فرض کافی نیست:

1. در `frontend/components/blocks/BlockView.tsx` یک `case` برای `type` خودتان اضافه کنید، یا کامپوننت را جدا بسازید و همان‌جا صدا بزنید.
2. المان را در `frontend/lib/catalog.ts` هم بگذارید اگر می‌خواهید بدون `elements.json` در پالت باشد. اگر فقط `elements.json` باشد، ظاهر پیش‌فرض است و پالت از API پر می‌شود.
3. روی سرور `sudo site rebuild`.

صفحهٔ مدیریت اختصاصی را زیر `frontend/app/master/plugins/نام-افزونه/page.tsx` بسازید و همان مسیر را در `admin.path` بنویسید.

## ۷. افزونه Go

کد سرور باید داخل باینری باشد. Go افزونهٔ دینامیک پایدار برای این کار ندارد.

1. بسته را در `backend/internal/extend/samples/نام` بسازید.
2. در `init` آن، قلاب را ثبت کنید.
3. در `backend/plugins_register.go` یک blank import اضافه کنید.
4. `sudo site rebuild`.

نمونه: یک مسیر سلامت برای افزونه.

```go
package ping

import (
  "net/http"

  "github.com/mtma6991-arch/site/backend/internal/extend"
  "github.com/pocketbase/pocketbase/core"
)

func init() {
  extend.OnServe(func(se *core.ServeEvent) {
    se.Router.GET("/api/v1/ext/ping", func(e *core.RequestEvent) error {
      return e.JSON(http.StatusOK, map[string]string{"pong": "ok"})
    })
  })
}
```

و در `plugins_register.go`:

```go
import (
  _ "github.com/mtma6991-arch/site/backend/internal/extend/samples/ping"
)
```

`extend.OnBoot` بعد از ساخته‌شدن مجموعه‌ها اجرا می‌شود و برای اطمینان از وجود یک مجموعهٔ اضافه مناسب است. خطا در OnBoot بالا آمدن سرور را متوقف می‌کند؛ خطا را خودتان لاگ کنید و nil برگردانید اگر خرابی افزونه نباید کل سایت را بخواباند.

مجموعهٔ تازه را با همان الگوی `backend/internal/bootstrap/bootstrap.go` بسازید: اگر نبود `core.NewBaseCollection`، فیلدها، بعد `app.Save`. قانون API مجموعه را خالی نگذارید مگر عمداً بخواهید از REST خام PocketBase عمومی باشد. مسیرهای خودتان را زیر `/api/v1/ext/...` بگذارید و با `apis.RequireAuth("users")` ببندید.

داده در SQLite داخل `/var/lib/site/pb_data` است. داشبورد خود PocketBase فقط روی خود سرور، `http://127.0.0.1:8090/_/`، با همان ایمیل مدیر در دسترس است و از اینترنت پروکسی نمی‌شود.

## ۸. امنیت

- زیپ را فقط مدیر نصب می‌کند.
- شناسهٔ پوشه محدود است تا روی فایل‌های سیستم نوشته نشود.
- فرم عمومی نرخ‌محدود است و فیلد مخفی `company` را دور می‌ریزد.
- رمز مدیر حداقل ۱۰ نویسه است.
- فایل رسانه نوع‌های مجاز دارد و SVG پذیرفته نمی‌شود.
- اسنیپت HTML و JS قدرت کامل در مرورگر بازدیدکننده دارد.

## ۹. چک‌لیست انتشار افزونه

- `plugin.json` نام، شناسه، نسخه و توضیح دارد.
- روی یک سایت آزمایشی زیپ را نصب و روشن کرده‌اید.
- اگر Go یا React دارد، `site rebuild` را در راهنمای افزونه نوشته‌اید.
- دادهٔ کاربر را در فایل کنار کد ذخیره نمی‌کنید؛ از مجموعهٔ PocketBase استفاده می‌کنید.
- افزونه را خاموش می‌کنید و مطمئن می‌شوید سایت عمومی نمی‌شکند.

نسخهٔ هسته در پاسخ `GET /api/v1/health` فیلد `version` است. اگر `minCms` شما بالاتر از آن است، در توضیح افزونه بنویسید.
